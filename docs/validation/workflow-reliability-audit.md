# 多轮 CST 流程可靠性复查（2026-11-09）

## 范围与结论

逐页检查用户指定的完整工程对话及当前仓库实现，并只读检查其建模/编排源码。
未打开、修改或停止来源工程，未刷新其 worker。此报告只保留通用故障类型，
不发布私有几何、器件参数、矩阵或日志。

主要问题是：用户要求没有统一的跨轮次当前版本；配置接口之间缺少语义完整性检查；
已有技能中的调用方职责没有可执行交接记录。插件是技能包，并不自动执行每条规则。
因而仅追加“不要忘记”不能提供可靠保证。

工具调用记录也表明技能曾实际读取，不能笼统归因为“完全没有加载 skill”。但后期
续跑出现只读入口前 28/32/50 行的命令；入口后半段和条件引用不能因此视作已执行。
现在入口明确要求完整读取选中的 SKILL.md，再按操作读取所需引用，避免用标题摘要
替代验收流程。该证据能证明读取范围不足，不能证明每一次遗漏都由此造成。

| 观察到的问题 | 根因与边界 | 本轮处置 |
|---|---|---|
| 多次补标参数、逐段/逐管独立性需用户提醒 | 只画主要尺寸，缺少实体段与参数覆盖表 | 建模/绘图增加覆盖表和独立性检查 |
| 导入后引用不存在的实体导致写入围栏 | 预计名称代替导入后的真实名称；当前工程脚本已增加读回 | 二极管加载明确只读映射后再批量写入，不放松恢复围栏 |
| 参数扫描曾清除原始结果 | 旧参数更新路径执行完整重建 | 当前已有 parametric update 修复，本轮不重复修改；继续保持结果身份及保存读回要求 |
| 修改端口阻抗后馈线未同步，用户需澄清渐变和终接 | 端口参考、源/负载、传输线几何、数据归一化被混为一项 | 四项分别记录和核验；保留用户指定固定段 |
| 整机最高覆盖频率自适应导致磁盘求解 | 子模型设置直接扩大到整机，混频覆盖上限被用于网格自适应而缺成本重评 | 网格技能补整机成本与覆盖/自适应区分，保留已批准的成本控制策略 |
| HB 有效数据已存在但自动模板缺节点 | 模板复制未充分核对当前节点/探针映射；链顺序验证不是回调验证 | 新增代表工况模板执行检查，区分物理求解失败与后处理失败 |
| 完整扫频/交付内容需反复提醒 | 代表点验收与最终交付清单没有持久关联 | 阶段清单保留完整工况集合和必需图，逐项比对实际证据 |
| 仓库入口与安装包不完全一致 | build_plugin 未包含 skills/README.md，测试还显式跳过此文件 | 修复打包并以实际 ZIP 内容回归验证 |
| 多个技能来源和运行版本并存 | 插件缓存不等于源码，worker 不自动重载 | 明确选定来源与四层版本核对；本轮不修改用户全局配置 |

用户中途改变设计意图，不作为最初实现错误统计。真实未知写入需要恢复审阅，也不能
为了减少询问而取消围栏。对话显示的卡顿或遗忘无法单凭摘要归因于模型、宿主自动
技能选择或上下文压缩；以上结论限于可观察的遗漏、源码及打包证据。

## 本轮实现与验证范围

新增 `skills/cst-sessions/scripts/check_workflow.py`，纯标准库、只读、可随插件分发。
要求显式工程身份、阶段所需项、输入依赖、期望值、证据文件摘要和 JSON pointer。
检查缺证据、输入变化、工程切换、证据覆盖/丢失、节点缺失和实际值不符，返回非零。
它不能验证清单是否列全，也不能证明记录内容真实或代替 CST 原生验收。
现有 solve/service/MCP 不自动调用该脚本，必须由遵循技能的调用方在提交前接入。

离线回归使用合成数据，验证输入失效和文件证据检查，以及打包后技能/脚本/入口的
一致性。未在真实 CST 求解中验证这套交接流程，不声称消除所有遗忘或已热更新旧对话。
针对性 17 项、完整离线回归 1561 项通过（2 项排除，9 项既有端口朝向警告）；七个
修改的 skill 格式检查通过。首次受限完整测试未完成，权限环境调整后的完整重跑通过。
发布包及本机安装升级到 0.3.24，安装文件与包逐项核对；活跃对话重新读取状态未验证。

## 尚未解决的强制执行问题

0.3.24 增加的是完整读取指令和可调用检查器，不能据此宣称截断读取已被系统阻断。
当前插件只分发技能/文档/脚本，没有在宿主通用文件读取或 shell 工具上注册拦截器。
读取命令成功、文件哈希或人工勾选均不能证明全文已进入上下文，更不能证明正确理解。

0.3.25 把用户的禁止要求置于每个技能入口前部，明确因输出限额截断也必须补齐，
上下文压缩后仅剩摘要须恢复全文；补齐前不执行依赖的写入和求解。这仍是代理必须
遵守的指令，不是宿主技术强制。未修改或宣称能够控制宿主的内部上下文保留机制。

其余未解决项：现有 service/MCP 提交未强制调用 workflow 检查器；检查器不能发现
清单中根本未声明的需求/依赖；旧对话重新加载和真实工程中的端到端行为尚未验收。
后续确定性保护应检查实际操作的必要输入与证据，而非接受一个“已读 skill”布尔值。
