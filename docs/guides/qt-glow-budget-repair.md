# Qt 阴影装饰窗与正文预算误报修复

2026-11-04。来源记录中，同组空标题 QtitanTitleBarGlowWindow 在正文预算尚余时可识别为 decoration，
预算耗尽后的同类窗口因 read_errors 而被标为阻塞。已保存副本与模型计算状态由所属会话核对；
这里不记录模型、路径、PID、HWND、参数或结果，也不重写原任务失败历史。

根因是先执行 UIA/正文读取，再把“读取无错误”作为识别装饰窗的必要条件；
共享三秒预算耗尽产生的错误使真实装饰窗失去该身份。

修复位于 `cst_solver/dialogs.py`：先执行严格结构校验，再决定是否需要读正文。
仅精确 glow 类、空标题、可见/响应中、同进程 Qt QWindowIcon owner、相同且已知的创建身份、
没有原生子控件及已知正文/按钮/进度时，保留原窗口快照并标为非阻塞装饰窗。
该分支不调用 UIA，记录结构证据来源，而不是把未读正文改成“读取成功”。
缺少 owner/身份、身份不同、有标题、非响应、有原生子控件或不同窗口类时继续常规读取；
预算或 provider 失败仍报告 unknown/blocking。真正 Connection Check 等窗口不会随 glow 一起排除。

离线回归使用合成 Win32 快照，未枚举真实窗口或执行 CST：
多 glow 在预算耗尽时保持 decoration；不消费 UIA；逐项否定结构条件时仍阻塞；
存在子控件时不抑制；同批真实模态窗口继续报告。原有读取失败/严格装饰窗回归也保留。

1274 passed、3 skipped（MCP extra 缺失）、2 deselected（实机/UI 未执行）。独立代码审查无阻塞发现。
