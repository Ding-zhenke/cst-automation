# 参数预览与分阶段构建

## 参数与几何审阅

多轮任务先恢复[当前要求与阶段清单](../../cst-sessions/references/workflow-checkpoint.md)。
用户要求“所有参数/每段独立”时，先列实体段→参数名→值/公式→单位→共享或独立→图页
的覆盖表，再出图和建模。逐管同初值不等于共享同一个参数；未标注段不能默认为固定。
无法一页容纳时增加局部视图，而不是只挑主要尺寸。按实际轮廓区分中心线长度与线宽。

1. 先读目标工程及当前要求，明确长度/频率单位、全局坐标、传播方向、层叠、材料、
   端口编号与法向、源工程和输出位置。参数值、公式、说明分开记录；不从旧案例猜值。
2. 每个用于几何建模的参数都要写 `expression`，让参数名能对应到结构及物理意义。
   用所属 Python API `app.para(name, value, expression=description)` 写入；会话参数更新
   使用 `set_parameters` 的 `values` 和 `expressions`，其底层调用同一
   `app.para(name, value, expression=description)` API。`expression` 是参数说明文本，
   至少写清结构部位/物理含义与单位；对派生参数还要说明其依赖参数及关系。可执行数值
   或 CST 联动公式放在 `value`，例如 `value="w_main/2"`、
   `expression="主线半宽（mm），由主线宽度 w_main 派生"`。不要把公式塞进说明字段，也
   不要只靠参数名、注释或建模代码替代 `expression`。独立尺寸和派生尺寸保留为参数及
   联动公式，不要用数值展开破坏可扫描的依赖关系。
   明确要求保留并更新当前工程时，已建好模型的逐点参数更新使用会话 `set_parameters`；当前 `app.update()` 调用
   CST `RebuildOnParametricChange(False, False)` 刷新受影响的历史块，并在调用失败时
   报错。后续 solve 不再追加一次重建。参数刷新与结构源代码变更/完整重建是不同路径；
   需要完整重建时先保留所需结果，并按实际工程核验结果是否留存，不把参数刷新回执当成
   结构重建或求解证据。
3. 新建或实质修改几何前，从**同一组真实参数**生成等比例预览；俯视/剖面按需要选，
   标出孔、薄层、开口、接触、端口、坐标和关键尺寸，等待审阅。已有批准范围继续
   有效，不反复确认例行步骤。只有文字概念或截图看起来相似不算几何核对。
4. 扫描前离线检查参数极值与约束：正尺寸、内外半径、净间隙、接触/重叠、薄层位置、
   端口离结构的关系。变拓扑与同拓扑扫参区别处理；不直接删除仍被公式/历史引用的参数。

## 按依赖阶段构建

- 先单位、参数、组件、曲线组和材料，再基础实体/轮廓、定位与复制、布尔、局部特征，
  最后材料赋值、边界、端口和监视器。按实际依赖调整，不把每个基础体都当成一个完整
  重建阶段，也不在整个设备结束后才首次检查。
- 基础体优先对应 API；孔洞明确使用切割体及 subtract。区分 `component:name`
  与 `curve:name`，指定组名、材料、轴向、中心与尺寸的实际语义。
- 布尔前明确目标与工具、保留材料/独立对象的意图。孔、相交、插入和合并不互换。
  参数化后要检查工具是否被消费、组件是否变化、是否出现零厚度/多余小实体。
- 变换明确中心、矢量、角度、复制/原位、重复数、合并和对象种类；端口不随实体自动
  旋转。局部 WCS 完成后恢复全局坐标，再设置全局端口或对称边界。面/棱 ID 会随
  布尔与参数改变，按实际几何重新拾取；不复用失效编号。
- 明确要求原位修改已有工程、需要改删对象时，用明确名称的
  rename/change_component/delete_solid 或 delete_curve_item。若任务属于代码源驱动的
  模型修改，则改代码并从空工程重建，不把逐项删除旧对象当作默认路径。导入的外部文件要记录真实
  来源、单位、依赖与可搬移性，不能因通用路由未开放就另连工程。

复杂操作的顺序与限制见 [装配、坐标、材料和端口](model-operations.md)。
