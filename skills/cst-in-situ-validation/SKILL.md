# 在实际工程中验证并迭代

把当前工程任务作为主线。已有接口虽只有离线验证，仍可在授权的实际工作中使用；不因缺少单独的验收机器或历史实机记录而停止，也不另建无关工程或额外启动昂贵求解。按任务使用 [cst-sessions](../cst-sessions/SKILL.md) 和相应建模、电路、求解、结果或诊断技能。

## 操作前

1. 确认所属会话、工程、已授权任务及当前阶段；查看当前运行库源码、`docs/PUBLIC_API.md`、`docs/VALIDATION.md`、已有测试和相关实机记录。复用已有实现、命令依据、参数和前期准备，不从零重做；历史证据不能代替本次工程实际状态。
2. 根据当前任务选择能自然观察到的验收点：原生配置及读回、保存/关闭/重开、结果与日志、实际求解及数值证据分别记录。已有接口未做实机测试时，明确预期行为和失败时如何保全现场，继续执行已授权的正常工程步骤；不把离线测试或接口返回当作更高等级的证明。
3. 不扩张用户授权：不为验证而追加求解、修改拓扑、覆盖结果或中断正在运行的工作。合理的小范围离线检查可直接开展；需要额外昂贵扫描或改变工程目标时，先完成不依赖它的工作，再说明实际缺项。

## 现场发现问题

- 查原任务回执、原生消息、日志、实际弹窗和进程归属，定位是接口、版本、工程输入还是求解问题；保留首次错误和阶段。SDK 未返回、任务正在运行、可能部分写入或状态未知时，不盲目重试、重放、另开同一工程或强制终止；按所属会话的恢复和诊断流程处理。
- 可复用的库缺陷就地修复：先更新跨包公共协议，再改通用 Python 实现、显式 service/MCP 路由及相关技能；补能验证实际故障的离线测试，保持项目私有参数和器件结论留在用户工程。只修当前任务需要的问题，不复制领域专用代码到通用库。
- 源码更新不等于运行中的 worker 已加载。仅在原 SDK 调用已返回、DE 空闲、队列无运行/等待任务且无未处理弹窗时，使用已验证的 worker 退出和恢复机制，在同一 root/reference、同一身份下恢复；同时防止检查与退出之间新任务进入。保留工程及 CST DE，不为加载新版中断正在执行的任务。没有可靠退出机制或无法排除竞态时不强杀、不声称重载成功。代码修复、离线测试与推送可独立继续，并报告实际加载状态和等待条件。
- 原调用结果明确、工程状态可核对、且后续步骤仍在已授权范围内时，在同一工程中按已知依赖阶段继续或有界重试；保留原错误和修复前后证据。不要把未知写入当作失败已回滚，也不要以新任务 ID 绕过未决状态。

## 回馈通用库

- 任务中获得的真实证据及时写入 `docs/VALIDATION.md`：接口/版本、运行或读取的实际阶段、观察结果、未验证项及可追溯的脱敏证据位置。验证了读回就记录读回，验证了求解才记录求解；有限功率结果、收敛和性能各自独立，不夸大结论。
- 用户已要求将干中验证及修复回馈仓库：完成必要测试、检查差异并保护并行工作后，按仓库约定提交并推送 `main`；仅提交通用代码、测试、技能与脱敏证据，不上传 CST 工程、私有几何/器件参数、凭据、工作目录或用户数据。主会话负责推送，不能安全合并时保留可审阅提交并说明阻碍。
- 即使该轮只能验证其中一个阶段，也可准确记录并发布已完成的通用修复；不能将未验证的阶段写成通过。向用户报告当前工程任务结果、库修复、实际验证等级和剩余具体缺项；继续当前工程主线，不把维护库变成额外的独立项目。
