# 现场缺陷和实机证据的维护

## 修复可复用缺陷

用当前仓库的源码、相关测试、实机记录和 `docs/PUBLIC_API.md` 核对失败接口、加载版本及复现条件。变更跨包协议时先更新公共契约，再修改通用 Python 实现、显式 service/MCP 路由和受影响技能。用离线测试覆盖实际故障。工程私有参数、几何和器件结论保留在用户工程。

任务确实需要加载修复后的代码时，再处理 worker 升级。核对已加载版本、原 SDK 调用已返回、所属 DE 空闲、队列没有在途或等待任务、弹窗均已处理。按[所属会话的 worker 交接](../../cst-sessions/references/session-operations.md#worker-交接)阻止检查与退出之间接收新任务，保留工程、DE、原 root/reference 和身份。缺少已验证的退出或防竞态机制时，保留当前 worker，记录加载状态及等待条件。代码修复、离线测试和已获授权的发布可独立进行。

原工程恢复后，只对已知缺失的步骤作有界重试。保留修复前后的回执，核对工程状态再判断结果。

## 登记与发布

将实际使用的接口、版本、本次观察到的阶段、结果、仍缺的证据及可追溯的脱敏出处写入仓库 `docs/VALIDATION.md`。按实际操作区分配置、原生读回、保存重开、求解、数值收敛和性能，涉及有限功率时记录对应激励。沿用工程现场已得到的证据，额外昂贵扫描需有相应授权。

已有库维护授权时，完成必要测试、审阅差异并隔离并行工作，由主会话按仓库约定提交并推送 `main`。发布内容限通用代码、测试、技能和脱敏证据。保留私有工程、用户数据与凭据。若有合并冲突，保全可审阅的改动并报告具体阻碍。向用户交付本次修复及验收范围后，继续原工程任务。
